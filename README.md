# VoiceAgent

VoiceAgent is a multi-component application that combines:

- a **LiveKit-powered Python voice agent** (`backend/agent.py`)
- a **FastAPI RAG chat API** (`backend/main.py`)
- a **React + Vite frontend** (`frontend/`)
- a **retrieval-augmented knowledge base** built from document data

The project is intended to power a voice-based assistant that listens to spoken questions, retrieves relevant context from a document, and returns spoken answers.

## Architecture

### Backend 9

The backend contains two main paths:

1. `backend/agent.py`
   - Uses `livekit` for real-time voice session management
   - Uses `deepgram` for speech-to-text and text-to-speech
   - Uses a Groq-style LLM for answer generation
   - Uses a RAG engine to retrieve relevant knowledge from a configured data source

2. `backend/main.py`
   - Implements a FastAPI chat API
   - Uses `langchain` + `ChatGroq` for retrieval QA
   - Exposes `/chat` and user credit endpoints
   - Uses the same RAG engine for document retrieval

### RAG Engine

The retrieval engine is implemented in `backend/rag_engine.py`:

- loads text or PDF data from `settings.data_path`
- creates or loads a Chroma vector store
- performs similarity search to find relevant context

By default, `data_path` is `./articulo.pdf`.

### Frontend

The frontend lives in `frontend/`:

- built with React and Vite
- uses LiveKit client components for voice session playback
- uses Firebase for auth / transcript storage hooks
- communicates with the backend API and the voice agent

## Prerequisites

- Python 3.11+
- Node.js / npm
- Docker (optional, for container-based startup)
- A LiveKit project and credentials
- API keys for:
  - `GROQ_API_KEY`
  - `DEEPGRAM_API_KEY`
  - `LIVEKIT_URL`
  - `LIVEKIT_API_KEY`
  - `LIVEKIT_API_SECRET`
  - `FIREBASE_SERVICE_ACCOUNT`
  - optional `ELEVENLABS_API_KEY`

## Setup

### Backend

1. Open a terminal in `backend/`
2. Create and activate a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

3. Install backend dependencies:

```powershell
pip install -r requirements.txt
```

4. Create or update `backend/.env` with your keys.

The backend expects values for:

- `GROQ_API_KEY`
- `DEEPGRAM_API_KEY`
- `LIVEKIT_URL`
- `LIVEKIT_API_KEY`
- `LIVEKIT_API_SECRET`
- `FIREBASE_SERVICE_ACCOUNT`
- `ELEVENLABS_API_KEY` (optional)
- `FIREBASE_STORAGE_BUCKET` (required for persistent audio, for example `voiceagent-f1e76.firebasestorage.app`)
- `AUDIO_RETENTION_HOURS` (optional, defaults to `24`)
- `CORS_ORIGINS` (required in production; comma-separated frontend origins)
- `DATA_PATH` (optional, overrides default document path)
- `PERSIST_DIRECTORY` (optional)

Generated MP3 files are uploaded by the backend to Firebase Storage at
`audio/{userId}/{conversationId}/{audioId}.mp3`. Firestore stores the conversation,
message, and audio metadata; the MP3 binary is never stored in Firestore. The
frontend receives the current response only and no conversation-history endpoint
is exposed. Firebase Storage rules deny direct client access. Cleanup runs at
backend startup and before a new upload; configure the bucket lifecycle rule
from `storage.lifecycle.json` for production enforcement.

### Frontend

1. Open a terminal in `frontend/`
2. Install frontend dependencies:

```bash
npm install
```

3. Configure frontend environment variables in `frontend/.env` or your shell:

- `VITE_BACKEND_URL`
- `VITE_LIVEKIT_URL`
- Firebase config variables: `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, etc.

## Running locally

### Run the backend API

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn main:app --host 0.0.0.0 --port 8000
```

### Run the LiveKit voice agent

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python agent.py start
```

### Run the frontend

```bash
cd frontend
npm run dev
```

## Docker Compose

You can also start backend and frontend together with Docker Compose:

```powershell
docker-compose up --build
```

This will start:

- backend API on `http://localhost:8000`
- frontend on `http://localhost:3000`

## Deployment

The project includes a `render.yaml` manifest for deployment on Render.com.

It defines:

- a Python backend service
- a Python/livekit worker for the voice agent
- a static React frontend site

## Notes

- `agent.py` uses LiveKit only for session signaling/audio; the text answer itself is generated by the backend agent code.
- `main.py` is a separate FastAPI chat API and does not use LiveKit directly.
- Default knowledge comes from `articulo.pdf` unless overridden by `DATA_PATH`.

- If the agent returns `I am sorry, but I don't know the answer...`, it means the query could not be matched strongly to the available context.

## Project structure

- `backend/`
  - `agent.py` — LiveKit voice agent entrypoint
  - `main.py` — FastAPI chat API
  - `rag_engine.py` — retrieval + vector store logic
  - `config.py` — environment settings
- `frontend/` — React UI and LiveKit client
- `data/` — additional knowledge sources
- `articulo.pdf` — default document used by the backend RAG engine
